# 主管共创应用清单

以下均是“建议”，除明确写为现有能力外，尚未上线。

## 优先级 A：先减少丢失事件的调查成本

1. **丢失物品调查助手**：输入物品、区域、最后确认时间，推荐摄像头与最小回看窗口，由主管人工串联证据。
2. **摄像头健康巡检**：发现遮挡、模糊、过曝、夜视异常、时间漂移和录像中断。
3. **主管人工标注闭环**：把候选标为确认、纠正、驳回或无法判断，并记录原因，用真实反馈评估误报和漏报。
4. **事件复盘台账**：长期保留脱敏事件元数据、覆盖缺口和改进项，不长期复制视频。

## 优先级 B：用现有门区和业务路线扩展

1. **非工作时间通行复核**：把值班时段与门区通过候选结合，产生待核实清单，不能自动认定违规。
2. **多人紧邻通过或尾随复核**：利用现有多人节点生成专项复核卡，结论仍由人工确认。
3. **物料交接追踪**：把仓储、品检、打包、出货摄像头候选与 ERP/WMS 时间记录结合。
4. **重点区域变化提醒**：只对明确区域和物品类别做候选提醒，并配套误报处理和人工关闭流程。

## 优先级 C：完成基础验证后再做

1. **接近实时的门区异常提醒**：当前系统是次日批处理，需要先验证资源、误报率和响应责任。
2. **跨区域物料时间线**：需要现场确认摄像头拓扑和时钟，不能用视觉相似直接认定同一物体。
3. **管理看板**：展示覆盖率、待复核量、录像缺口和处理时效，不展示未经核实的人员结论。

## 每个新应用的验收问题

- 它解决的具体业务损失是什么？
- 谁负责收到候选、多久内处理？
- 哪些摄像头和时段得到正式授权？
- 什么是人工确认，什么只是模型候选？
- 如何测量误报、漏报和证据覆盖？
- 录像、截图和事件元数据各保留多久？
- 账号如何按人撤销，离岗后如何停权？
- 失败时是否明确显示未知，而不是给出错误的“正常”？

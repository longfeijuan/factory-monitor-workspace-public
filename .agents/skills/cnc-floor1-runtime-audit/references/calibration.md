# 一楼电脑锣双通道灯位标定

## 当前版本

`cnc-floor1-green-blink-v3.0-dual-view` 于 `2026-09-02` 修正物理机台映射：通道49只负责可见的1、2、3、5、6号机，通道2“一楼鱼眼1”只补通道49看不到的4号机。此前v2.1把物理5号机的亮灯记到了4号框，并把错误的5号框报成0%；该版本对物理机台编号的结果已失效，不能继续引用。

v3保留首个10秒窗口只有1个绿帧时固定延长到20秒的复核规则。4号机鱼眼灯位沿用同一仓库早期已审核的`2560×1440`物理4号ROI，并在`2026-09-02 14:30`已知亮绿灯窗口重新验证：39帧中35帧达到绿灯阈值。用户提供的鱼眼标注确认了1至6号物理编号，并再次确认通道49看不到的是4号机、通道49画面中亮绿灯的是5号机。

六台机坐标和唯一画面来源的机器可读来源是仓库根目录的 `config/cnc-floor1-runtime-v3.json`。本文不重复一份可执行坐标，避免两处配置漂移。v2配置仅保留用于解释旧结果，不再用于正式查询。

## 为什么不能自动移动灯位

机台指示灯、环境反光和现场人员衣服都可能产生绿色像素。自动搜索最亮绿点会在不同录像、不同电脑或不同采样窗口选择不同位置，破坏跨电脑一致性。正式规则必须先由人工确认六个物理灯位，再把固定矩形写进新版本配置。

## 需要重新标定的信号

- 解码尺寸或画面视角与配置记录明显不符；
- 六个固定框大面积落在地面、墙面、人员或非对应机台；
- 多个采样点中所有六台都长期没有任何绿色响应，但现场画面可见灯亮；
- 摄像头移动、旋转、缩放、裁切或通道映射改变。

出现这些情况时必须让质量闸门失败，不得回退成0%。

## 变更步骤

1. 只读抽取覆盖不同时间的代表帧，确认录像机、通道、画面尺寸和角标时间。
2. 在代表帧上逐台框定唯一物理指示灯，至少用一个已知运行窗口验证闪烁响应。
3. 新建策略版本和新配置文件；不要改变已有版本的语义。
4. 添加合成测试、配置自检和一段经人工复核的黄金时段。
5. 提交并推送Git；其他电脑拉取同一提交后再查询。

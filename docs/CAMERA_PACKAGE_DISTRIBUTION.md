# 监控资料分发与权限说明

## 处理原则

“黄伟工作群”是内部原始发布渠道，不是公开分发版使用者必须加入的群。项目采用两级分发：

- 内部资料同步人：经公司授权取得原始资料，负责在内部环境完成下载、校验和脱敏审核。
- 公开版使用者：无需 GitHub 账号，只读取公开仓库中已经审核的脱敏摄像头目录、问答规则、技能和只读工具。

不得把群文件权限不足当成技术故障绕过。需要查看原始群文件时，应由群管理员邀请或由内部资料同步人按公司授权处理。

## GitHub 公开分发

公开仓库为 `longfeijuan/factory-monitor-workspace-public`。普通使用者可以匿名下载或克隆，不需要 GitHub 账号。

公开仓库只接收经过内部审核的无历史脱敏快照：

- 不从公开仓库反向同步原始资料；
- 不在公开仓库中处理真实凭据、录像、截图或人员参考图；
- 普通使用者只通过 Release 安装器或 `git pull` 获取已发布版本；
- 公开仓库写权限仅由发布维护人持有。

不得向普通使用者分发维护人的 GitHub 账号、Token、SSH 私钥或其他发布凭据。

## 普通使用者

```bash
git pull
python3 scripts/monitor_self_check.py
python3 scripts/sync_camera_catalog.py --check
```

每次回答应读取 `camera-data/current/SOURCE.json`，说明正在使用的文件名和发布时间，并称为“仓库内置版本”。没有核对内部原始发布渠道时，不得称为“群内最新版本”。

## 内部资料同步人

内部资料同步、脱敏审核和发布必须在公司授权环境内完成。公开版使用者不运行原始资料同步入口。

确认变更只包含脱敏资料并通过完整质量门后，才允许由发布维护人生成新的无历史公开快照。账号、密码、网络地址、原始录像、截图、人员参考图和本机运行结果不得进入公开 GitHub。

## 实时录像权限

公开 GitHub 只解决监控规则和脱敏资料的分发，不代表拥有真实录像权限。需要核查真实画面的人员仍须在每台电脑上单独取得：

- 通过公司批准安全渠道取得的4台 NVR 只读连接项，并录入本机 Windows 凭据管理器或 macOS 钥匙串；
- 公司内网或获批 VPN；
- 任务所需的本机私密校准资料。

普通使用者不需要钉钉 `dws` 或黄伟工作群权限。只有指定资料同步人需要访问内部原始发布渠道。公开链接、GitHub 仓库和安装器均不得携带 NVR 地址、用户名或密码。

缺少其中任何一项时，可以回答目录、规则和操作方法，但真实录像结论必须标为“未知/待核实”。
